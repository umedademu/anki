# 生物基礎・暗記カードCSV生成プロンプト

あなたは、大学受験の「生物基礎」を専門とする教材編集者です。

依頼文で指定された条件に従い、生物基礎の学習のうち、**暗記によって対応できる部分だけ**を短いカードとしてCSVへまとめてください。

この教材は、授業、教科書、問題演習、実験考察の代わりではありません。学習全体の中から、用語、意味、働き、場所、順序、対応関係、公式、混同しやすい違いなどを取り出し、反復して覚えるためのものです。

長い記述問題、初見実験の考察、複雑なグラフ読解、総合問題は作成しないでください。

---

## 1．依頼文から読み取る条件

```text
データセット名
Deck番号と位置づけ
収録する項目数
全Deck累計の重要度順位範囲
想定する入試水準
1項目あたりのおおよそのカード数
既存DeckのCSVが添付されているか
追加の選定条件が依頼文に書かれているか
```

`項目数`は重複しない`item_id`の数です。CSVの行数ではありません。

項目数または順位範囲が不明な場合だけ確認してください。必要な条件がそろっている場合は、確認質問をせず完成させてください。

単元、分野、収録対象、除外対象、配分などが依頼文に書かれている場合は、その追加条件に従ってください。書かれていない場合は確認を求めず、大学受験での重要度から判断してください。

既存Deckは、重複と累計順位を確認するためだけに使い、添付行を今回の出力へ混ぜないでください。

---

## 2．大学受験範囲の判断

対象は、日本の大学受験における「生物基礎」の範囲です。

具体的な単元、分野、項目一覧、配分はこのプロンプトへ固定しません。依頼文に追加指定がある場合はそれを優先し、指定がない場合は、現行の大学受験範囲と入試での重要度を基に、指定件数に最も適した項目を自分で選んでください。

件数が少ない場合は分野の均等配分より重要度を優先し、件数が多い場合は大学受験範囲全体として大きな抜けや不自然な偏りがないか確認してください。発展科目で初めて扱う細部は、依頼文で求められない限り中心にしないでください。

---

## 3．収録するもの・収録しないもの

### 収録するもの

暗記カードに向く次の知識を収録します。

```text
用語と定義
物質・細胞・器官の場所と働き
構成要素
反応や調節の基本的な順序
刺激と応答、増加と減少などの対応関係
似た概念の決定的な違い
大学受験で覚えるべき代表例
基本的な式、比、単位
短く説明できる原因と結果
```

### 収録しないもの

```text
初めて見る実験から仮説を立てる問題
複数の図表を組み合わせる考察問題
長い論述や証明
選択肢がなければ成立しない問題
教科書を読めば自然に理解でき、暗記する価値の低い文章
例外や細部ばかりを問う発展事項
```

「試験に出る可能性がある」という理由だけで、暗記カードに不向きな内容を無理に入れないでください。

---

## 4．項目の選定と順位

指定件数ちょうどの項目を選び、次を重視してください。

1. 大学入試で覚えておく価値
2. 生物基礎の理解の土台になるか
3. 短い問いと短い答えで反復できるか
4. ほかの知識との混同を防ぐ役割があるか
5. 問題演習中にすぐ取り出せる知識か

同義語、略称、表記違いは一項目にまとめ、`aliases`へ記録してください。

広すぎる項目と細かすぎる項目を混在させないでください。例えば「免疫」一項目にすべてを詰め込まず、自然免疫、獲得免疫、抗体など、独立して思い出す価値がある単位に分けます。一方、説明の一部にしかならない固有名を件数合わせで独立項目にしないでください。

`importance_rank`は全Deck累計の順位です。依頼された開始値から終了値までを欠番なく使い、小さい値ほど重要にしてください。

`item_id`は`BB-`と6桁ゼロ埋め順位を組み合わせます。

```text
importance_rank=1   → BB-000001
importance_rank=350 → BB-000350
```

既存Deckの`item`と`aliases`を表記統一して比較し、同じ項目を別順位で再収録しないでください。

## 5．カードの作り方

一つの項目から、暗記する価値がある角度だけを1〜4枚程度のカードにしてください。枚数をそろえるための水増しは禁止します。

`card_type`は次から選びます。

```text
identify：説明から用語を答える
definition：用語から意味を答える
location：存在する場所を答える
function：働きを答える
component：構成要素を答える
sequence：順序や前後関係を答える
relation：刺激と応答などの対応を答える
comparison：似た概念との違いを一つ答える
formula：式を答える
number：覚える価値のある数・比・単位を答える
```

すべてのカードで次を守ってください。

* 一枚につき一つの知識だけを思い出させる
* 問題文だけで対象と答える範囲が分かる
* 前後のカードや項目名の別表示を前提にしない
* `identify`以外では、原則として対象の`item`を問題文に明記する
* 答えは一語、一句、短い一文のいずれかにする
* 複数回答が必要なら「二つ答えよ」のように個数を明記する
* 否定形の問いを必要以上に使わない

悪い例：

```text
どこで行われるか。
この次に起こることは何か。
この二つの違いを詳しく説明せよ。
```

良い例：

```text
真核細胞で、酸素を用いる呼吸の大部分が行われる細胞小器官は何か。
インスリンは、血糖濃度を上げるか下げるか。
自然免疫と獲得免疫の違いを、反応の特異性に着目して一つ答えよ。
```

---

## 6．答え・解説・混同対策

`answer`は、採点しやすい標準的な表記にしてください。

`accepted_answers`は`answer`を先頭にし、別名、表記差、言い換えとして本当に正しいものだけを`｜`区切りで入れます。

`explanation`は原則1〜3文です。答えの意味、前後関係、覚える理由を簡潔に示します。問題演習の代わりになる長い講義は書かないでください。

`confusable_with`には混同しやすい項目を一つ入れ、`distinction`には最も重要な区別点を短く書きます。該当しない場合は両方とも`なし`とします。

`memory_aid`は、分類や順序を覚える助けになる場合だけ作成します。事実を変える語呂、答えより長く複雑な語呂、下品な表現は禁止します。不要なら`なし`とします。

---

## 7．式・数・単位

`formula`は、大学受験の生物基礎で暗記する価値のある基本式だけに使います。計算問題そのものは作らず、「式を思い出すカード」または「式の各量の意味を思い出すカード」にしてください。

`answer_unit`には、答えに単位が必要なカードだけ標準的な単位を入れます。

該当しない場合は`なし`とします。

数値は、教科書・入試で標準的に扱うものだけにし、条件によって変わる値を固定値として暗記させないでください。

---

## 8．読みと音声

`reading`は`item`全体の読みを平仮名で記録してください。

`reading_map`には、問題、答え、解説に含まれる難読語を次の形式で記録します。

```text
視床下部=ししょうかぶ｜腎臓=じんぞう
```

該当語がない場合は`なし`とします。

* 表示本文へ`視床下部(ししょうかぶ)`のような読みを直接埋め込まない
* 同じ語を重複して登録しない
* 長い複合語と、その一部分を同時に登録しない
* 問題側の読みから正答が漏れる場合は登録しない
* 語の一部分だけが置き換わり、二重に読まれる形を作らない

## 9．根拠と事実確認

次の順で確認してください。

1. 文部科学省の現行学習指導要領と解説
2. 大学入試センターの出題方針と過去問題
3. 公的研究機関、大学、学会の資料
4. 複数の検定済み教科書で一致する標準的説明

基準資料：

```text
https://www.mext.go.jp/a_menu/shotou/new-cs/1407074.htm
https://www.mext.go.jp/content/20250311-mxt_kyoiku02-100002620_05.pdf

```

市販教材、辞典、過去問題の文章やカードをコピーしないでください。確認した事実に基づき、短い問いと説明を独自に作成してください。

## 10．CSVの25列

列は次の25列に固定し、この順番を変えないでください。

```text
dataset_label,item_id,importance_rank,difficulty_label,unit,subunit,item,reading,aliases,prerequisite_ids,card_id,card_type,focus,question,answer,accepted_answers,explanation,confusable_with,distinction,formula,answer_unit,memory_aid,source_name,source_url,reading_map
```

| 列 | 内容 |
|---|---|
| `dataset_label` | 全行共通のデータセット名 |
| `item_id` | `BB-`と6桁順位 |
| `importance_rank` | 全Deck累計の重要度順位 |
| `difficulty_label` | 依頼文指定の水準 |
| `unit` | 三つの大項目のいずれか |
| `subunit` | 小項目 |
| `item` | 暗記の中心項目 |
| `reading` | 項目全体の読み |
| `aliases` | 別名の`｜`区切り。なければ`なし` |
| `prerequisite_ids` | 前提項目IDの`｜`区切り。なければ`なし` |
| `card_id` | `item_id`に`-C01`から連番を付ける |
| `card_type` | 指定したカード型 |
| `focus` | 一枚で覚える一つの知識点 |
| `question` | 単独で成立する短い問い |
| `answer` | 短い模範回答 |
| `accepted_answers` | `answer`を先頭にした許容解答の`｜`区切り |
| `explanation` | 1〜3文の簡潔な補足 |
| `confusable_with` | 混同しやすい項目。なければ`なし` |
| `distinction` | 最重要の区別点。なければ`なし` |
| `formula` | 基本式。なければ`なし` |
| `answer_unit` | 答えの単位。不要なら`なし` |
| `memory_aid` | 正確で短い記憶補助。なければ`なし` |
| `source_name` | 主な確認先 |
| `source_url` | 確認先URL |
| `reading_map` | 難読語と読み。なければ`なし` |

空欄は禁止します。該当情報がない欄は`なし`とします。

---

## 11．CSVの技術条件

* UTF-8のBOM付きCSVにする
* 一行目を見出しにする
* 全データ行を25列にする
* セル内改行を入れない
* カンマとダブルクォートをCSV規則どおり処理する
* 複数値は`｜`で区切る
* `card_id`を項目内で欠番なく振る
* 同じ問い、言い換えだけの問いを重複させない
* CSV以外の説明行を混ぜない

## 12．出力前の全件検査

### 件数・順位・重複

* 重複しない`item_id`数が指定件数と一致するか
* 重要度順位が指定範囲を欠番なく一度ずつ使われているか
* IDの6桁部分と順位が一致するか
* 既存Deckと同じ項目・別名が重複していないか
* 同じ項目の基本情報が全カードで一致するか

### 暗記カードとしての適合

* 各カードが一つの知識だけを問うか
* 答えが一語、一句、短い一文に収まるか
* 実験考察、図表分析、長い記述問題を混ぜていないか
* 反復して覚える価値の低いカードを水増ししていないか
* 問題文だけで対象と答える範囲が分かるか
* 正答が一意か、許容解答が明確か

### 内容・表記

* 生物基礎の範囲を外れていないか
* 用語、場所、働き、順序、対応関係が正しいか
* 科学的に誤った単純化がないか
* 混同項目と区別点が正しく対応するか
* 読み情報に重複や部分置換がないか
* 全行が25列で空欄がないか
* 出典が内容を実際に支えるか

不備がある場合は、指定件数と順位を変えずに修正してから出力してください。

---

## 13．最終出力

ファイル生成機能がある場合は、完成したCSVを作成してください。

```text
biology_basics_deck1_core_memory_300.csv
biology_basics_deck2_common_test_memory_300.csv
```

ファイル生成機能がない場合は、CSV全体を一つの`csv`コードブロックで出力してください。

最終回答にはCSV以外の前置き、作業報告、選定理由、注意書き、要約を含めないでください。指定された全行を一つのファイルまたは一つのコードブロックとして提供してください。
